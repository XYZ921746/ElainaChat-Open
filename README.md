一个**以插件（Mod）为核心**的开源 AI 角色聊天应用。程序本体只有文字聊天 + Agent 能力，
角色怎么呈现、界面长什么样，全都交给**可装可卸的扩展包**决定。

通过自带 API Key（BYOK）直连服务商 —— **没有作者网关、没有共享套餐、没有内置密钥**。

本仓库基于 [shuixinggangzheng/ElainaChat-Open](https://github.com/shuixinggangzheng/ElainaChat-Open)（MIT 协议）二次开发。
主线是**让「扩展」成为一等公民**：新增一种呈现方式不需要改宿主代码，
卸掉一个扩展包不会拖垮主程序，也不该让其它能力跟着失效。

> 本项目处于测试状态，可能存在未知问题。完整改造记录、踩坑与验证数据见 [`开发文档.md`](开发文档.md)。

## 为什么是「Mod 优先」

大多数聊天应用把花哨功能**焊死在主程序里** —— 你不用也得装着，卸不掉，坏了还会拖垮整个应用。
本项目的取舍相反：

| | 传统做法 | 本项目 |
| --- | --- | --- |
| 新功能怎么加 | 改宿主代码 | **加一个目录**（`web/mods/<名字>/`） |
| 不想要怎么办 | 忍着，或自己改代码 | **关掉开关 / 删掉目录** |
| 插件崩了 | 整个应用白屏 | **只标记那个插件出错**，其余照常 |
| 未启用的插件 | 照样加载、占内存 | **不注入脚本、不占内存** |
| 依赖缺失 | 静默失败，界面缺一块 | **设置里标「缺依赖」+ 控制台日志** |
| 打包体积 | 全都要带上 | **纯净版约 10.8 MB**，资源按需下载 |

支撑这套说法的是具体机制，不是口号：

- **清单驱动**：加载器只认 `manifest.json`，**不硬编码任何插件名**
- **失败隔离**：插件的加载与初始化都包在 `try/catch` 里，一个坏 mod 绝不白屏整个应用
- **依赖声明 + 环形检测**：`manifest.after` 做拓扑排序，缺依赖会**明确报出来**
  （「装了 galgame 却没有立绘」这类无声故障是重点防的对象）
- **能力解耦**：Agent 的标签协议（文件 / 命令 / 手机操作）**不寄生在任何扩展包里** ——
  卸掉 Live2D 不会让 Agent 系统跟着失效（这条是踩过坑才补上的，见「AI 标签协议」一章）

## 下载

**安卓版**：到 [Releases](https://github.com/XYZ921746/ElainaChat-mod/releases/latest) 下载
`ElainaChat-mod-v1.3.0-lite-debug.apk`（**约 10.8 MB**），
在手机上允许「安装未知来源应用」后安装。

> **这个 APK 是「纯净版」** —— 只含程序本体 + 插件**代码**，
> **不含 Galgame 界面、桌宠的图片素材与 Live2D 模型**。那些按需下载，见下方
> 「[扩展包](#扩展包mod--插件)」。
> 好处是安装包小（含资源时约 33.6 MB），且不必为你用不到的资源买单。

**电脑版**：克隆本仓库，双击 `启动.bat` 即可（**零依赖、零构建**，只需已安装 Node.js ≥ 20）。

```bash
git clone https://github.com/XYZ921746/ElainaChat-mod.git
cd ElainaChat-mod
# 双击 启动.bat，或：
node web/serve.mjs
```

浏览器打开 `http://127.0.0.1:4173`。

## 扩展包（Mod / 插件）

程序本体只有**文字聊天 + Agent 能力**。**Galgame 界面、桌宠、Live2D 模型都是扩展包**，按需安装。

### 包含哪些

都在同一个 [Releases 页面](https://github.com/XYZ921746/ElainaChat-mod/releases/latest)，
**每个包一个直链，按需下载**（不用下整个大包再解压）：

| 扩展包 | 内容 | 大小 | 说明 |
| --- | --- | --- | --- |
| `elaina-avatar` | 9 张立绘 + 情绪识别 | 10.15 MB | **公共依赖**，被下面两个共用。装完不显示界面，也不用开 |
| `galgame` | 31 张场景背景 + 全屏剧情界面 | 7.24 MB | 打字机对话框、粒子特效，与主界面共用同一份对话数据 |
| `pet` | 桌宠悬浮层（代码） | 0.01 MB | 立绘复用 `elaina-avatar`，回复时自动切表情 |
| `live2d-deepseek` | Live2D 模型 `deepseek` | 3.08 MB | 视频通话用 |
| `live2d-elaina-default` | Live2D 模型 `伊蕾娜·默认` | 2.14 MB | 视频通话用 |

> **`galgame` 和 `pet` 依赖 `elaina-avatar`**。只装前者不装它，界面能打开但**没有立绘** ——
> 程序会在设置里标出「缺依赖」并写进控制台日志，不会静默失败。
>
> 模型包的文件名是 ASCII（`live2d-elaina-default.zip`），但**装好后在程序里显示为原名**
> `伊蕾娜·默认` —— 名字在 zip 内部保留着，外壳文件名只是为了下载链接可靠。

### 怎么安装

**方式一：应用内上传（推荐，手机也能用）**

1. 到 [Releases](https://github.com/XYZ921746/ElainaChat-mod/releases/latest) 下载需要的 `.zip`（**不要解压**）
2. 打开程序 → **设置 → 插件 → 上传安装** → 选中那个 zip
3. 安装完在列表里**打开对应的开关**（插件默认关闭）

**方式二：丢进目录（电脑版）**

把 zip 直接放进 `web/mods/` 目录，然后在 **设置 → 插件** 点「重新扫描」。
服务端会在下次扫描时自动解压 —— 不用解压、不用重启。

> 安装包在装好后会被**自动清理**（它是一次性安装包）。所以「删掉插件目录」
> 就是有效的卸载方式，不会被重新装回来。应用内也有「删除」按钮。

**Live2D 模型**走的是另一条路（它们是模型不是插件）：
设置 → **Live2D** → 上传模型 → 选那个 zip。或把解压后的模型**目录**放进 `web/live2d/models/`。

### 装完在哪用

| 扩展包 | 开启位置 | 使用位置 |
| --- | --- | --- |
| `galgame` | 设置 → 插件 → 打开开关 | 主界面出现全屏剧情模式入口 |
| `pet` | 设置 → 插件 → 打开开关 | 桌面上出现悬浮角色 |
| Live2D 模型 | 设置 → Live2D → 选模型 | 点「视频通话」时使用 |

> **所有插件默认关闭**，装完要手动开。这是刻意的 —— 插件会改动界面，
> 不该在你不知情时生效。

### 自己写一个插件

插件就是一个目录 + 一份清单。宿主**不认识任何具体插件**，所以加功能不用碰主程序。

```text
web/mods/my-mod/
├─ manifest.json     # 必需：id / name / version / entry / styles / defaultEnabled / after
└─ index.js          # 入口：用 ElainaMods.register(id, factory) 注册
```

```js
// index.js —— 拿到宿主给的 api，别直接摸宿主内部
ElainaMods.register('my-mod', (host) => {
    host.log('已加载');

    // 往 system 提示词里追加一段（插件影响模型行为的唯一入口）
    host.setPromptHint('当用户提到「天气」时，用 <weather>…</weather> 包裹城市名。');

    // 读当前对话 / 发消息（走宿主既有链路，记忆、续跑、停止都自动生效）
    host.on('reply-done', (text) => host.log('AI 回复了', String(text).slice(0, 40)));

    return {
        // 用户在插件列表里关掉它时调用 —— 把界面收起来
        setEnabled(on) { /* ... */ },
    };
});
```

宿主 API 是一张**收窄的清单**（不是把 `window` 丢给插件）—— 这样宿主才能重构内部实现
而不弄坏插件。完整清单见 `web/js/mods.js` 的 `createHostApi()`：
`getConversation` / `getMessages` / `getUiMode` / `sendUserMessage` / `renderText` /
`injectStyle` / `setPromptHint` / `on` / `emit` / `has`。

> **安装插件 = 信任它的代码**（它在页面同源环境里运行）。请只装自己信得过的。

### 为什么扩展包不放在仓库里

这些包合计 **约 22.6 MB，其中 87% 是图片**（PNG / JPG / moc3）。
Git 对二进制**无法有效增量压缩** —— 改一张立绘，历史里就多存一整份，
clone 会越来越慢。所以：

* **仓库只放插件源码**（`manifest.json` / `index.js` / `style.css`，共约 60 KB）——
  它们要跟主程序接口对齐、要跑测试，属于开发的一部分
* **资源走 Releases**，用 `node scripts/pack-assets.mjs` 打包后上传

自己改完插件后重新打包：

```bash
npm run pack:assets               # 打包全部（输出到 dist/assets/）
npm run pack:assets galgame       # 只打某一个
node scripts/pack-assets.mjs --list   # 先看看会打什么
```

打包格式有约定（写进脚本注释了）：插件 zip 的**根目录直接是文件**，
模型 zip 的**根目录必须是模型名那一层** —— 因为模型是按目录名识别的。

## 更新日志

### v1.3.0-mod

**Agent 的标签协议不再寄生在 Live2D 里（架构）**

- 修掉一个**能力寄生**问题：AI 标签的剥离（`stripTags`）与分发（`drive` →
  `handleAgentOperation`）原先整个长在 `web/live2d-video.js` 里，而它是
  **全部 `[操作:…]` 标签的唯一分发器** —— 文件操作、电脑命令、手机操作、整理记忆全在里面。
  宿主各处又都写成 `if (window.Live2DCall) { … }`，于是 **Live2D 一旦不在
  （被卸掉 / 该文件加载失败），Agent 系统会整体失效，标签还会漏给用户看**。
  这不是界面耦合，是能力寄生
- 现拆到 `web/js/agent-tags.js`（**宿主自有**）：剥离与分发归宿主，
  Live2D 只提供**表现**（表情 / 动作 / 情绪 / 位置 / 大小 / 背景 / 口型），
  并通过 `registerOperationHandler` 追加它独有的**水印 / 静音**两个操作 ——
  它可以**扩展**这条分发链，但不再**拥有**它
- 顺带修掉 `Live2DCall` 对象里两个 `drive` 键重名（`driveText` 成了死引用）
- 新增 `scripts/check-agent-tags.mjs`：用**故意不提供 `window.Live2DCall`** 的沙箱
  证明解耦成立（剥离干净、操作照常分发、表现层缺失不抛异常）

**权限边界：局域网设备登录后与本机同等能力**

- 原先「允许操作电脑」只对 `127.0.0.1` 开放，局域网一律降级到「仅应用文件夹」。
  现改为按**是否已认证**判定（本机免密 / 局域网登录），`/api/agent/activity` 一并放开
- ⚠️ 相应地，**访问密码从「聊天室的钥匙」变成「整台电脑的钥匙」** ——
  所以本次必须同时补上配套防护（见下一条）
- 「看电脑在干什么」（前台窗口 / 进程）也放开给已登录设备

**登录防爆破与密码强度（新增 `server/auth-guard.mjs`）**

- **密码强度**：至少 8 位且同时含数字 / 小写 / 大写；另拒弱口令表、键盘顺子（`qwerty`）、
  「弱口令 + 数字尾巴」、字符种类过少（如 `Aaa1aaaa`）
- **三层防爆破**：单 IP 指数退避（30 秒起、每次翻倍、上限 1 小时）；
  **计数只在成功时清零**（锁定到期不重置，持续攻击只会越锁越久）；
  **全局限流**（换 IP 也绕不过 —— 局域网里换地址太容易）
- 换掉旧的固定窗口（5 次 / 锁 60 秒）—— 那等于告诉攻击者「每 60 秒可以试 5 次」，
  保持低频就能长期爆破
- 如实说明的代价：**全局冻结可被利用做拒绝服务**（攻击者制造足够失败，
  正常设备也登不进去），这是全局限流固有的取舍；冻结最长 5 分钟

**Agent 文件操作：覆盖已有文件 = 修改，必须确认**

- 旧实现是无条件 `writeFile` —— 目标已存在就**静默覆盖**，而提示词却写着
  「AI 没有修改权限（仅可新建）」。这个落差有两个害处：模型可能拒绝合理请求，
  也可能照做而用户毫无防备
- 现在服务端补**覆盖闸门**（`needOverwrite`，**两种模式都拦**），提示词同步改成
  「可以覆盖，但每个对话首次会确认一次」，两边对齐
- **不可逆操作的确认粒度改为「每对话一次」**：旧行为每条危险命令都弹，
  用户会退化成闭眼点允许，闸门反而失效；判断前移到「要不要开全权限」
  （设置页列出后果清单 + 开启时确认一次）

**其它修复**

- 修掉「高级」设置栏首块多出的一条横线（从「记忆」时代残留 ——
  v1.1.0 把记忆等块搬去「能力」栏后，日志升为首块但分隔线没删）

### v1.2.0-open

**免费语音：Edge TTS**

- 设置 → 语音 → 语音服务商 里新增「Edge TTS（免费，临时使用）」，无需 API Key，选了就能用，
  并已设为默认。中文（晓晓 / 晓伊 / 云希 / 云扬 / 东北话）+ 日语 + 多语种音色可选
- **两条路都不在网页里拼协议**：浏览器 JS 的 `new WebSocket()` 不允许自定义请求头，
  而微软端点要校验浏览器指纹，网页直连必然 403。所以电脑版由**本机服务代合成**、
  安卓版走**原生层**，协议实现在各自那边
- 界面如实提示：这是微软给 Edge 浏览器用的服务，**没有稳定性承诺**，临时用没问题，
  长期建议用付费接口

**AI 手机操作：只确认一次**

- 原来"同一次运行内允许过就不再问"是**按操作名去重**（点击 / 滑动 / 输入各问一次），
  一次任务还是被打断两三次。新增「每次运行只确认一次」并设为默认：
  **本轮确认过任意一个操作，后面的敏感操作全部放行**，停止完全靠悬浮窗
- 任意系统命令（dangerous 级）在任何策略下仍然单独询问
- 修掉一个只有**真实时序**才暴露的 bug：AI 每步之间有续跑间隔，
  间隔超过 600ms 会把"本轮"重置，于是每步都变成"本轮第一次"，每步一弹 —— 策略等于没改。
  现在"本轮"以**一条 AI 回复**为单位，续跑间隔不再影响它

**聊天停止按钮**

- AI 回复期间发送按钮变红、图标切成方块，点击**立即中断**（含打断等待中的确认弹窗），
  语音一起停；停止后安静收尾，不弹错误框

**安全加固（本次审计发现并修复的两个真漏洞）**

- **修掉一个存储型 XSS**：应用文件夹模式"禁止写 `.html`/`.js`/`.svg`"的防护，
  可以被 Windows 的 `x.html::$DATA`（NTFS 交换数据流）、`x.html.`（尾随点）绕过 ——
  落盘后**文件名就是 `x.html`**，静态服务照样当 HTML 执行。判据已改为
  "先剥掉 ADS / 尾随点 / 尾随空格，再取扩展名"
- **修掉一个 SSRF 绕过**：本地中转的内网判定按字符串前缀比较，漏掉了
  `::ffff:127.0.0.1` 这类 IPv4-mapped IPv6 写法（它**连的就是 127.0.0.1**）。
  已改为"解析成 IP 后统一规范化判定"
- 登录页补上 `X-Frame-Options: DENY`（原先只有静态页面有，登录页漏了 = 点击劫持有了落点）
- 新增 `scripts/check-security-hardening.mjs`（101 项，含端到端与变异测试），已挂进 `npm run check`

**副屏监视窗**

- AI 用「模块」后端操作手机时跑在**独立虚拟副屏**上，物理主屏看不到。
  现在可把副屏画面实时搬进应用（入口在运行状态条上，只在模块后端时出现），
  知道 AI 正在点什么、界面变成了什么样

- **大小与位置调整框**：底部「调整」按钮开关；框体贴合模型的实际绘制范围（不是画布留白）并逐帧跟随；角手柄等比缩放，边手柄单轴，框内拖动移动；每个模型独立记忆

## 三、跨设备数据同步

原版的数据存在浏览器 `localStorage` 里，每台设备各存一份——电脑上聊的记录、填的 API Key，手机上看不到。

本改版把需要共享的项同步到服务端 `data/` 目录（**按用途分类存放**，不再挤在一个文件里）：

- **同步内容**：设置、API Key、聊天记录、分类、收藏、喜欢的台词、角色卡、记忆核心、Live2D 偏好，共 11 项
- **本机独有项会自动补齐**：服务端缺、本机有的键会补推上去，不会因为服务端已有别的数据就漏掉
- **实现方式**：包装 `localStorage.setItem`，业务代码零改动；关闭页面前用 `sendBeacon` 兜住未发出的写入
- **不落仓库**：`data/` 已在 `.gitignore` 中（里面还有自签证书），不会进版本库

### 数据怎么分类存放

```
data/
├─ store.json           设置 / API Key / UI 偏好（约 1.5 KB，几乎不变）
├─ characters/          人设卡 —— 一卡一文件
│  ├─ index.json          卡片顺序 + 当前选中
│  └─ <卡片id>.json       每张卡的内容（可单独拷走分享）
├─ conversations/       聊天记录 —— 一对话一文件
│  ├─ index.json          对话顺序
│  └─ <对话id>.json       每个对话的内容（可单独拷走分享）
└─ memory/              记忆 —— 一类目一文件
   ├─ diary.json          日记（会持续增长的那个）
   ├─ promise.json        承诺
   ├─ preference.json     用户偏好
   ├─ plan.json           计划
   ├─ motivation.json     动机
   └─ pivotal_memory.json 关键记忆
```

**为什么要拆开**：原来所有数据都在 `store.json` 一个文件里（32 KB，聊天记录占 34%、人设卡占 55%）。
一旦写坏就是**全部数据一起丢**，而且人设卡没法单独分享。现在按用途分文件，各自独立。

记忆单独拆的理由更具体：**六类的增长特性完全不同** —— `diary` 越写越长，
其余五类很小且很少变。混在一起意味着"加一条日记要把整个记忆重写一遍"。

**升级不会动你的数据**：代码更新只覆盖程序文件，`data/` 目录原样保留。
首次启动时会自动把旧的单文件数据迁移成分类文件（幂等，重复启动不会重复迁移，也不会覆盖已更新的内容）。

### 备份与恢复

设置 → 高级 → **我的数据**：

- **导出备份**：把全部数据打包成一个 JSON 文件下载（含版本号与时间戳），换机器/重装前先存一份
- **导入备份**：选择备份文件合并回来。默认**合并模式**——只覆盖备份里有的项，本机其它数据保留
- **状态显示**：直接看到人设卡 / 对话 / 记忆各有多少、数据在哪个目录

对应的后端接口：`GET /api/data/export`、`POST /api/data/import`、`GET /api/data/info`。

**刻意不同步的两项**：当前打开的会话（各设备独立）、模型尺寸记忆（跟屏幕大小有关）。

## 四、手机端与网络访问

### 一个端口同时认 http 和 https

浏览器地址栏输入 `192.168.0.200:4173` 时，会自动补成 `http://`。而麦克风只在 `https` 或 `localhost` 下可用——这是浏览器的硬性规定，应用层改不了。

所以本改版在 TCP 层做了协议分派：同一个端口既接受明文 HTTP，也接受 TLS。你只需要记一个地址。

- 局域网用 http 访问会自动跳到同端口的 https
- 本机（`localhost` / `127.0.0.1`）不跳转——它本来就是安全上下文，跳过去只会白点一次证书警告
- 接口请求和静态资源不跳转，只有页面导航会跳
- 想强制留在 http：访问 `?stay=http`，会用 Cookie 记住

### 自签证书自动管理

- 首次启动用本机 openssl 自动生成，SAN 里带上网卡的所有局域网 IP
- **到期前 30 天自动续期**，不用管；`--reset-cert` 可手动重签（换了局域网 IP 时需要）
- 证书与私钥存在 `data/`，已 gitignore
- 你自己放的证书不会被覆盖——自动续期只对自己签发的生效

手机首次打开会提示证书不受信任，点「高级」→「继续前往」即可。

## 五、AI 标签协议

LLM 的回复里可以携带标签来驱动模型表现和应用功能，**这些标签不会显示给用户**。

| 标签 | 作用 |
| --- | --- |
| `[情绪:开心\|难过\|生气\|害羞\|惊讶\|委屈\|思考\|平静]` | 映射表情与嘴型幅度 |
| `[表情:xxx]` | 播放指定表情文件 |
| `[动作:xxx]` | 播放指定动作 |
| `[位置:left\|center\|right]` | 移动模型位置 |
| `[大小:大\|小\|特大\|65%]` | 调整模型大小 |
| `[背景:深蓝\|星空\|...]` | 切换通话背景 |
| `[操作:打开视频通话\|结束通话\|整理记忆\|静音\|隐藏水印\|...]` | 执行应用内操作或文件操作 |
| `[任务:每天 09:00 ...]` | 创建定时任务 |

**跨模型自适应**：模型列表接口会返回每个模型可用的表情与动作文件名，系统提示词动态注入这份清单，AI 直接选用真实文件名。情绪词与语义键经过「语义映射 → 精确匹配 → 子串兜底」三级解析，换任何模型都自动适配。

### 这套协议归宿主所有，不归 Live2D

标签的**剥离**与 `[操作:…]` 的**分发**在 `web/js/agent-tags.js`（宿主自有），
**不在** `live2d-video.js` 里。这不是洁癖，是踩过坑：

原先这两件事整个长在 Live2D 那个文件里，而它是**全部 `[操作:…]` 标签的唯一分发器**
（文件操作 / 电脑命令 / 手机操作 / 整理记忆都在其中）。宿主各处又都写成
`if (window.Live2DCall) { drive(); stripTags(); }` —— 于是 **Live2D 一旦不在
（卸掉、或该文件加载失败），Agent 系统会整体失效，标签还会漏给用户看见**。

现在分工是：

| 文件 | 职责 |
| --- | --- |
| `web/js/agent-tags.js` | 标签**剥离** + `[操作:…]` **分发**（宿主能力，永远可用） |
| `web/live2d-video.js` | 只做**表现**：表情 / 动作 / 情绪 / 位置 / 大小 / 背景 / 口型 |

Live2D 通过 `registerOperationHandler` 把**水印 / 静音**这两个它独有的操作
**追加**进分发链 —— 它可以扩展这条链，但不再拥有它。表现层缺失时，
`ElainaTags.drive()` 照常分发操作，只是跳过表现。

`scripts/check-agent-tags.mjs` 用**故意不提供 `window.Live2DCall`** 的沙箱钉住这一点：
剥离要干净、操作要照常分发、表现层缺失不许抛异常。

## 八、Agent 文件操作

LLM 可用标签请求本地文件操作：

- `[操作:列出文件 路径]`、`[操作:查看文件 路径]`、`[操作:保存文件 路径|内容]`
- **权限分两级**：默认「仅应用文件夹」，可选「允许操作电脑」（风险自担）
- 局域网设备**登录后与本机同等能力**（可读写任意路径、可执行命令）—— 见下方「两种模式的边界」
- 操作结果以「【AI 操作结果】」回填对话；报错由 AI 用自然语言解释
- **做完会自动接着做下一步**（读取 → 写入 → 再读取……），不用你说"继续"

### 两种模式的边界

| | 🔒 限制（默认） | 💻 允许操作电脑 |
|---|---|---|
| 可读写范围 | 仅 `web/`（本应用文件夹） | 电脑上任意路径 |
| 执行命令 | **不可用** | PowerShell / cmd |
| 写 `.html`/`.js`/`.svg` 等可执行类型 | `web/` 内**拒绝** | 不做类型限制 |
| 碰范围外的位置 | 就那一次问你 | — |
| 谁能用 | 本机 + **已登录的局域网设备** | 本机 + **已登录的局域网设备** |
| 未登录的请求 | 一律拒绝（401） | 一律拒绝（401） |

**权限边界只由"是否已登录"决定，不再区分本机/局域网**。本机（`127.0.0.1`）免密即管理员；
局域网设备通过访问密码登录后拿到同等能力。因此 ——

> ⚠️ **访问密码 = 这台电脑的钥匙**，不只是"聊天室的钥匙"。
> 登录后的设备能读写任意文件、能执行任意命令。请务必设强密码。

**两种模式都拦的（共同下限）**：

- **覆盖已有文件 = 修改，必须经你同意**。写一个已存在的文件时，服务端返回 `needOverwrite`，
  由你确认后才真正落盘（`overwrite:true`）。旧实现是无条件 `writeFile` ——
  目标已存在就**静默覆盖**，而提示词却写着"AI 没有修改权限（仅可新建）"，
  这个落差已修掉：现在服务端的强制与提示词的说法一致。新建文件不打扰。
- **删除类命令**（`del` / `Remove-Item` / `rmdir` / 格式化等）判为危险，需授权。
  文件操作接口本身**没有**删除/重命名/移动这三个动作。

**确认的粒度是「一次对话」，不是「每一次操作」**：

覆盖已有文件、以及删除这类不可逆的危险命令，**每个对话首次会问你一次**，同意后该对话内
不再重复询问；换一个对话重新问。安全命令（列目录、`git status`）直接执行。

> 为什么不做成"每次都问"：全权限下 AI 每一步都弹，用户会从"看清内容再决定"退化成
> "闭眼点允许"，最后那道闸反而等于没有。所以判断被前移到两个点上 ——
> **要不要开这个模式**（开启时设置页会列出全部后果并要你确认一次），
> 以及**这个对话里首次遇到不可逆操作时**。

> 也正因为如此，**开启「允许操作电脑」前请读一遍设置页里的后果清单**：
> 它能删除文件、覆盖已有内容、改注册表、关机、下载并执行网上的脚本，且大多不可撤销。
> 请只在你自己可控、且信任当前对话内容时开启（AI 的指令来自模型输出，
> 而图片文字、长期记忆、插件都可能影响它）。

### 自动续跑

一次操作**成功**完成后，结果会回灌给模型，它据此决定下一步 —— 所以"读取 → 写入 → 再读取"
这类多步任务能自己走完，不需要你每一步都催一句。

- **连续自动执行上限 8 步**，超过会停下并说明"先停在这里"（说一句"继续"会再给一批预算）。
  这个闸门是必要的：否则"读文件 → 续跑 → 再读 → 再续跑"会烧光额度。
- **随时可以停**：运行期间的状态条上有「停止」按钮，按了之后**不会再自动往下走**。
- 一条回复里有多个操作标签时，结果会合并成**一次**续跑，不会并发打出多个请求。
- **只有成功才续跑**。被拒绝、无权限、用户取消、失败说明这些**不会**触发下一步 ——
  否则会变成"被拒绝 → 又试 → 又被拒绝"的无效循环。

### 桌面不一定在 `C:\Users\<用户名>\Desktop`

桌面可以被**移动到任意位置**（桌面右键 → 属性 → 位置 → 移动），OneDrive 也会把它重定向走。
这时候按惯例猜路径必然失败 —— 而 AI 恰恰只会猜。

服务端会从注册表（`HKCU\...\Explorer\User Shell Folders`）读出**真实位置**，在「允许操作电脑」
模式下直接写进提示词，同时提供别名：

| 别名 | 含义 |
|---|---|
| `%DESKTOP%` / `~desktop` | 桌面 |
| `%DOCUMENTS%` / `~documents` | 文档 |
| `%DOWNLOADS%` | 下载 |
| `%USERPROFILE%` / `~` | 用户目录 |

于是 `[操作:保存文件 %DESKTOP%\便签.txt|内容]` 会落到用户真正的桌面上，不管它被移到哪里。
路径猜错时，报错里也会带上真实位置，AI 下一轮能自己纠正。

> 别名只在本机「允许操作电脑」模式下生效 —— 它先展开、后做权限判定，绕不过限制模式。
> 用 `LOG_TO_FILE=0` 启动可以关掉日志落盘（自动化场景用）。

## 十、访问控制与安全

服务默认监听 `0.0.0.0`（方便手机访问），因此必须做访问控制：

- **本机免密**：`127.0.0.1` 自动视为管理员，可修改访问密码
- **局域网设备必须登录**：登录后种 HttpOnly Cookie 会话。
  **登录后即与本机同等能力**（含执行命令）—— 所以密码是整台电脑的唯一防线
- **首次启动生成随机密码**（12 位，字符集排除 `0/O`、`1/l/I` 等易混字符）；
  改过之后只存 scrypt 加盐哈希，不再显示明文
- **密码强度校验**：至少 8 位且同时含数字 / 小写 / 大写；弱口令表、键盘顺子（`qwerty`）、
  "弱口令 + 数字尾巴"、字符种类过少都会被拒
- **登录防爆破（三层）**：
  - **单 IP 指数退避**：连续失败后锁定 30 秒起、每次翻倍，上限 1 小时
  - **计数只在成功时清零**：锁定到期不重置，持续攻击只会越锁越久
  - **全局限流**：所有来源的失败累计到阈值后，**全部登录临时冻结**
    （换 IP 也绕不过 —— 局域网里换个地址太容易；代价是正常设备也会被挡）
  - 被拦时回 `429` + `Retry-After`
- **CSRF 防护**：非 GET 请求校验同源；`/api/*` 的 GET 也拦跨站
- **Host 白名单**：防 DNS rebinding（否则攻击者域名解析到 127.0.0.1 就能拿到本机管理员身份）
- **隐藏文件禁止静态访问**、危险扩展名在解压时拦截、解压后总体积有上限（防 zip bomb）

> 防爆破与密码强度的实现集中在 `server/auth-guard.mjs`（纯逻辑、时钟可注入），
> 由 `scripts/check-auth-guard.mjs` 穷举断言 —— 因为"放开局域网执行命令"之后，
> 这套策略不再是加分项，而是权限模型的**必要组成**：它坏了，整台电脑就等于没锁。

**已知弱点（如实说明）**：

- **全局冻结是可被利用的拒绝服务**：攻击者只要制造足够多的登录失败，
  就能让**正常设备也登录不进去**。这是全局限流固有的代价 ——
  只按 IP 限流则换 IP 即绕过，两者不可兼得。冻结最长 5 分钟。
- **登录失败计数在内存里**，重启服务即清空（同时也意味着重启不保留"已锁"状态）。
- 会话 token 存在内存中，重启后所有设备需重新登录。

密码文件存在 **`data/auth.json`**（和 store、证书、日志同一处）。2026-09 之前它在 `web/.local-auth.json`，
属于"运行时私密数据混在源码目录里"；升级后首次启动会自动迁移，密码不变。

## 十一、BYOK 直连与本地中转

本改版是 BYOK：API Key 填在你自己的设备上，请求直接发往你指定的服务商，不经过任何作者服务器。

但"直连"在浏览器里有个绕不过去的限制 —— **CORS**。浏览器只把响应交给页面，前提是服务商返回了
`Access-Control-Allow-Origin`。现实是：

- 自建 OneAPI、厂商内测网关、很多第三方中转站**根本不发 CORS 头**；
- 有些连预检 `OPTIONS` 都直接回 405。

这时 `fetch()` 只会抛一句 `TypeError: Failed to fetch` —— 没有状态码、没有原因，看起来就像"网络断了"。
而 ChatBox、Cherry Studio 这类原生客户端用的是系统 HTTP 栈，**不受 CORS 约束**，
于是同一个 Key、同一个地址在它们那儿正常，在网页里就是连不上。

### 解决办法：`/api/relay`

页面由 `web/serve.mjs` 提供时，前端会自动探测同源的 `/api/server-info`，探测到了就改走 `/api/relay`：

```
浏览器 ──同源──▶ 本机 Node 进程 ──▶ 你的服务商
        （无预检）      （Node 没有 CORS 这回事）
```

- 前端只跟**同源**地址说话，连预检都不会触发；
- Key 只经过本机进程内存，**不落盘、不发给任何第三方**；
- 探测不到中转（例如直接双击 `index.html` 打开，`file://`）就自动退回原来的直连方式；
- 安卓 App 走原生插件（`ByokHttpPlugin`），本来就没有 CORS 问题，不经过中转。

### 安全边界

中转会把请求转发到你给的目标地址，所以做了三层限制：

- **需要登录**：接口挂在鉴权之后，未登录访客不能拿它当跳板；
- **封禁云元数据地址**：`169.254.169.254` 等云厂商元数据服务直接拒绝，防止被用来读本机凭据；
- **回环地址限本机发起**：局域网设备不能用它去打本机端口（SSRF），本机自己发起的请求放行 —— 因为 Ollama 就住在 `127.0.0.1`。

> 第三层曾经漏掉 `::ffff:127.0.0.1` 这类 **IPv4-mapped IPv6** 写法（它连的就是 `127.0.0.1`，
> 但按字符串前缀比较判不出来）。现已改为"解析成 IP 后统一规范化判定"，并加了端到端回归测试。
> 详见 [`开发文档.md`](开发文档.md) 8.42。

### 写入防护

「应用文件夹」模式下，AI **不允许写 `.html` / `.js` / `.svg` 等可执行类型** ——
这些文件落进 `web/` 后会以**同源**身份被浏览器执行，`.html` 直接构成存储型 XSS。

> 这条防护曾经用 `path.extname()` 判定，可被 Windows 的 `x.html::$DATA`（NTFS 交换数据流）、
> `x.html.`（尾随点）绕过 —— 落盘后文件名就是 `x.html`。现已改为"先剥掉这些尾巴再取扩展名"。
> 详见 [`开发文档.md`](开发文档.md) 8.42。

「允许操作电脑」模式**不做类型限制**（你已授权它操作电脑任意路径）。但 AI 若在该模式下
把 `.html` 写进 `web/`，同源风险依然成立 —— 这是刻意留给用户的取舍。

### 报错信息也一并改进了

- 中转自己连不上目标时（DNS 失败、超时、连接被拒）会返回**具体原因**，不再是笼统的"Failed to fetch"；
- 识别 FastAPI 系网关套在 `detail.error.message` 里的错误 —— 很多自建中转站是这个形状，
  不处理的话"模型名写错"会被报成一句无用的"请求失败"；
- 新增 `MODEL_NOT_FOUND` 错误码：地址和 Key 通、只是模型名不对时，直接提示去点「获取模型」。

### 上游的报错文案不一定在说真话

有些网关会返回**描述它自己约束、却读起来像在说你**的错误。已实测到的一例：

```
System message must be at the beginning.
```

字面意思是"你把 system 消息放到中间了"，但本应用的提示词分层发出的 system **全都在位置 0**，
完全合法，照样被拒。实测这个服务商**只接受至多一条 system**，多条连续 system 一律 400。

现在发送前会把**开头连续的 system 合并成一条**（对三种 API 格式都生效），内容一条不少、空行分隔，
夹在中间的 system 不动（那种情况是真错，合并会掩盖问题）。

顺带说明：如果错误提示里出现"图片转述"之类的字样而你**并没有发图**，那是旧版提示模板的锅 ——
任何 400 都会拼上那段话。现在只在本次请求真的带了图片时才会提图片。

**第二个例子**：

```
max_tokens must be greater than 1024 for manual Claude thinking
```

这句话里的 "manual Claude thinking" **不是你开的** —— 应用从不主动发送 `thinking` 参数。
它是中转站从**模型名后缀**推断出来的，见下一节。

### 模型名里的 `-thinking` 后缀

部分中转站（new-api 系）会**看模型名的后缀**替客户端决定要不要开启 Claude 的扩展思考：

| 模型名 | 效果 |
|---|---|
| `claude-sonnet-4-5-thinking` | 开启扩展思考，预算取 `max_tokens` 的 80% |
| `claude-sonnet-4-5-thinking-2000` | 开启扩展思考，预算固定 2000 |
| `claude-sonnet-4-5-nothinking` | 显式关闭 |
| `claude-sonnet-4-5` | 不涉及（走服务商默认） |

这不是 Anthropic 官方的约定，是**中转站的扩展**。它带来两个后果：

1. **`max_tokens` 必须大于思考预算**（Claude 的硬约束：`1024 ≤ budget_tokens < max_tokens`）。
   旧版中转站会直接拒掉 `max_tokens ≤ 1024` 的请求。本应用已给 `max_tokens` 一个 4096 的下限，
   并把 `-thinking-<数字>` 指定预算的情况一起算进去。
   **这条保底对三种对话格式都生效** —— 因为中转站的这条校验是**跨协议**的：
   用「OpenAI 兼容」格式调 Claude，转协议时同样会走到它。所以换成 OpenAI 格式并不能绕开，
   只要模型名里还带着 `-thinking` 就会撞上。
   （保底只在**模型名带后缀**时才抬 OpenAI 系的 `max_tokens`；普通模型名原样透传，不会被悄悄改大。）
2. **每一次对话都会走思考**，更慢也更贵。如果你只是照抄了中转站的示例模型名而并不想要思考，
   把后缀去掉即可。

遇到这类报错时，应用的提示里会直接点破这一点并告诉你下一步怎么做。

## 十二、排查与诊断

原版出问题时只能看浏览器控制台，手机上根本没法看。本改版补了两个手段：

### 启动窗口里的日志

- **请求日志**：来源 IP / 方法 / 路径 / 状态码 / 耗时，4xx 与 5xx 带标记。静态资源成功时不记录，避免刷屏
- **浏览器报错转发**：`console.error`、`console.warn`、未捕获异常、Promise 拒绝都会转发到启动窗口，带来源 IP 和页面路径。手机出问题时不用再去看控制台
- 启动窗口只打访问地址，说明类文字都放在应用内

### 日志落盘：`data/logs/`

启动窗口关掉就没了、滚几屏也找不回，所以上面这些日志**同时**写入 `data/logs/`。
格式参照 [AstrBot](https://github.com/AstrBotDevs/AstrBot)（loguru）：

```
[2026-09-21 20:55:13.289] [Core] [INFO] [serve:367]: serve.mjs 启动 pid=14204 版本 v1.0.0
[2026-09-21 20:55:13.555] [HTTP] [INFO] [serve:1390]: 127.0.0.1  POST  /api/relay  200  75ms
[2026-09-21 20:55:13.591] [Chat] [INFO] [serve:1594]: 提问：那我们去哪儿玩？
[2026-09-21 20:55:13.614] [Relay] [INFO] [serve:1633]: POST api.deepseek.com/v1/chat/completions -> 200 上游 26ms
[2026-09-21 20:55:13.635] [Chat] [INFO] [serve:1594]: 回复：你好呀，我是伊蕾娜。 今天想去哪儿？
[2026-09-21 20:55:14.102] [Relay] [ERRO] [v1.0.0] [serve:1624]: POST …/v1/chat/completions -> 400 上游 4ms << 上游报错：模型 deepseek-chat 不存在，请改用 DeepSeek-V4-Flash
```

- 级别四位：`DBUG` / `INFO` / `WARN` / `ERRO` / `CRIT`；`WARN` 及以上附版本号
- `[来源:行号]` 是**真实的调用点**，同一句报错出现在哪一行一眼能定位
- 时间一律**本地时间**（早期版本用的是 UTC，文件名和行内差 8 小时，已修）

### 日志级别：终端看全量，文件按级别收窄

**启动窗口（终端）永远显示全部级别**，设置里的级别只控制**写进文件**的内容。
这样"排查时终端不丢东西"和"日志文件不被 DEBUG 刷爆"可以同时成立。

设置 → **高级 → 日志** 可以随时调，**改完立即生效，不用重启服务**：

| 级别 | 会写进文件的内容 |
|---|---|
| `DEBUG` | 全部，含前端与第三方库（pixi / Live2D）的 `console.debug` 上报 |
| `INFO` | 默认，日常排查够用 |
| `WARN` | 只看警告与报错 |
| `ERROR` | 只看报错 |
| `CRITICAL` | 只看致命错误（如端口被占用导致服务没起来） |

同一个地方还能开关**对话追踪日志**（原来只能靠 `LOG_CHAT=0` 环境变量）。
选择会持久化到 `data/logs/log-settings.json`，下次启动沿用。

> 安卓 App 里**没有这一块** —— APK 不含 `serve.mjs`，日志落盘只存在于网页版（服务端）。
> 界面会整块隐藏，而不是留一个点了报错的控件。

**每次启动生成一组两个文件**，文件名就是启动时刻：

| 文件 | 内容 |
|---|---|
| `2026-09-21_20-55-13.log` | 主日志。一行一条记录，换行压成 `⏎`，方便直接 `grep` |
| `2026-09-21_20-55-13.trace.log` | 追踪日志。**LLM 的完整请求消息 + 完整回复 + 完整上游报错**，多行原样保留 |

**为什么分两个**：对话内容又长又私密，混在主日志里会把 `grep` 结果淹掉；而且排查时主日志常常
是要直接发出去的 —— 分开之后"要不要发对话内容"就变成一个明确的动作。

**只保留最近 10 次启动**（同一次的两个文件一起留、一起删）。单文件超 8 MB 会拆 `_2` / `_3`。

追踪日志里能看到什么：上游返回的**原始报错**（含 `detail.error.message` 这类嵌套文案）、
你当时**问了什么**（逐条消息，带角色和字数）、AI **答了什么**（流式回答会拼回完整正文）。
以下几种以前查不出来的情况，现在都有记录：

- **状态码 200，报错却藏在流式响应的 `data:` 行里** —— 以前表现为"AI 不回话"，日志里一片祥和
- **连接失败**（`ENOTFOUND` / `ECONNREFUSED` / TLS）—— 带上错误码，并且把当时问的内容也记下来
- **本地中转拒绝**（地址非法、协议不符、云元数据地址、SSRF）—— 以前完全静默

**隐私**：追踪日志含完整对话内容。启动横幅会提醒一句，对外分享前先看一眼。
在设置 → 高级 → 日志 里可以关掉（只留访问与错误摘要）。请求头一律不记 —— `Authorization`
就在里面，落盘等于把 API Key 写到磁盘上；请求体/响应体里的凭据形态另有脱敏兜底。

**开关**（环境变量，只作为**首次启动的初始值**；之后以设置界面为准）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `LOG_TO_FILE` | `1` | 设 `0` 完全不落盘（自动化场景用） |
| `LOG_CHAT` | `1` | 设 `0` 不写追踪日志 |
| `LOG_LEVEL` | `INFO` | 落盘级别（只影响文件，终端始终全量） |
| `LOG_DIR` | `data/logs` | 换日志目录 |

排查偶发问题时：重启服务 → 复现一次 → 把**最新那次启动的**主日志发出来即可；
如果涉及"AI 答得不对/上游报错"，把同名 `.trace.log` 一起看（发之前先扫一眼有没有不想外传的对话）。

> 目录里如果出现旧版的 `server.log` / `server.log.1`，首次启动会自动按修改时间改名成新格式，
> 之后正常参与轮转，不会留下不会再更新的孤儿文件。

### 诊断页

- `/diag-live2d.html` — 检查 Live2D 三个运行库是否加载、`PIXI.live2d` 是否挂载
- `/diag-asr.html` — 检查浏览器环境、麦克风权限、实际识别测试
- `/diag-param-bind.html` — 扫描某个模型的参数是否真正绑定到绘制

## 十三、AI 手机操作

让 AI 能**看见并操作手机**：点击、滑动、输入文字、读控件树、截图、启动应用。**仅安卓版 App 可用** —— 浏览器没有这层能力。

### 四种实现方式

入口在 **设置 → 高级 → 手机操作 → 「选择实现方式」**。默认不预设任何方式，需要你明确选一个。

| 实现方式 | 门槛 | 能力 | 中文输入 |
| --- | --- | --- | --- |
| **无障碍** | 免 root，开系统无障碍服务 | 点击 / 滑动 / 输入 / 读界面 / 截图（API 30+） | **只有它能可靠做到** |
| **Shizuku** | 免 root，装 Shizuku 并授权 | 同上 + 任意 shell + 启动应用 | 走无障碍 |
| **Root** | 手机已 root | 同上，不依赖电脑 | 走无障碍 |
| **模块** | 刷 KernelSU 模块 | 最强，**且不抢前台**（后台静默操作） | 走无障碍 |

每个卡片右下角有对应的「去设置 / 请求权限」按钮：原生层在场就真跳系统设置页或弹授权框，并把原生返回的文字展示出来（比如"没能拿到 root 权限：Permission denied"—— 那正是你下一步该做什么的依据）。

**没选实现方式时，设置照样能改**（总开关与确认策略跟"走哪条路"无关），只是状态文字标黄提示，真正执行时会被拒绝并回灌一句能照做的提示。

### 前提：提示词要告诉 AI 它有能力

光有执行链路不够 —— **系统提示词里必须声明这项能力，否则 AI 永远不会发出这些标签**，
表现就是"AI 好像不会操作手机"（它根本不知道标签存在）。

应用会按当前状态自动决定怎么注入：

| 状态 | 注入内容 |
| --- | --- |
| 网页版（没有原生设备层） | 不注入 —— 免得 AI 空谈一项做不到的能力 |
| APK 但还没选实现方式 / 总开关关着 | 「当前未启用」+ 明确禁止它输出手机标签 + 引导你去设置里开启 |
| 已选实现方式且已开启 | 10 个标签的完整清单 + 工作方式（先读控件树再点、中文输入先聚焦…）+ 反幻觉约束 |

所以**没启用时 AI 会如实说"还没开启"并告诉你去哪开**，而不是假装操作过了。

### 用法

AI 在回复里发标签，标签不显示给用户：

```
[操作:手机状态]   [操作:手机查看界面]   [操作:手机截图]   [操作:手机等待 800]
[操作:手机点击 500 800]        [操作:手机滑动 500 1500 500 500 300]
[操作:手机输入 你好世界]        [操作:手机按键 返回]
[操作:手机打开 包名]            [操作:手机命令 <任意 shell>]
```

### 运行时可停止

运行期间屏幕上方固定一条状态条（脉冲点 + 当前步骤与动作名 + 「停止」按钮）。点停止会中断在途请求、关掉等待中的确认弹窗，并拦截同一条回复里**后续所有步骤** —— 不会出现"点了停止还在动"。

### 敏感操作分级授权

| 等级 | 动作 | 行为 |
| --- | --- | --- |
| safe | 手机状态 / 查看界面 / 截图 / 等待 | 直接放行，不打扰 |
| sensitive | 点击 / 滑动 / 输入 / 按键 / 打开 | 按设置里的策略 |
| dangerous | 手机命令（任意 shell） | **无论策略如何都单独询问** |

策略三档：`always`（默认，每次都问）/ `run`（同一次运行内允许过就不再问）/ `off`。非法值一律回落到 `always`。

### 截图交给视觉模型看

原生把截图带回来，前端交给「设置 → 视觉」里配的多模态模型转述成文字，再回灌主模型。没配视觉模型时如实说明，并建议改用「手机查看界面」直接读控件树。

### 几个必须说明的坑

- **非 root 场景每次重启手机都要手动启动一次 Shizuku** —— 这是系统限制，不是应用的问题
- **小米 / POCO**：开发者选项要额外打开「USB 调试（安全设置）」（独立开关，不开就是点了没反应）；通知样式要切成「Android」才能填配对码
- **OPPO / 一加**：需关闭「权限监控」
- 厂商后台管理会杀前台服务 —— 加后台白名单、停用 adb 授权超时
- 中文输入**不走 `input text`**（只认 ASCII），一律改走无障碍的 `ACTION_SET_TEXT`，结果里会说明换了路

设计与厂商适配的完整讨论见 [`开发文档.md`](开发文档.md) 的手机操作章节。

## 原版已有的核心设计

这些是原版的设计，本改版完整保留：

- **BYOK 直连**：对话支持 OpenAI 兼容、Anthropic、Gemini、Ollama 等格式；语音支持 MiniMax、豆包、阿里千问 TTS，全部直连用户自己的账号（另有免费的 Edge TTS，见上）
- **密钥存储边界**：Android 用系统 Keystore 加密；Web 只使用 `sessionStorage`，不把 API Key 写进 `localStorage`
- **分层角色提示词**：角色协议、世界观、完整角色卡、会话设定、相关记忆、图片规则、本轮锚点、最近对话分层发送，避免长上下文后的人格漂移
- **记忆有预算而不是删数据**：按当前问题筛选相关记忆并限制每轮注入长度（约 4800 字符），原始记忆完整保留在本机
- **图片输入与 OOC 约束**：图片只作为待理解资料，不得改写角色身份与事实边界
- **语音识别走阿里云百炼**：原版的语音输入就是用阿里云百炼（DashScope）的 ASR 模型 `qwen3-asr-flash` 直连识别，界面文案也是「浏览器语音识别暂不可用，语音输入走阿里百炼」；浏览器内置识别只是标着「暂不可用」的备选通道
- **语音竞态保护**：自动播放尚未返回时再次点击同一气泡会复用同一任务
- **Android 原生网络插件**：绕过 WebView 的 CORS 限制，且只接受 HTTPS
- **可与正式版共存**：应用名 `ElainaChat Open`，包名 `com.elainachat.opensource`

```bash

```

> `android-app/android/app/src/main/assets/public/` 是 **`cap sync` 的产物**，不是 `sync:web` 写的。
> 只跑 `sync:web` 时它保持旧内容，`build:apk` 才会刷新 —— 排查"APK 里还是旧代码"时先看这一点。
>
> ⚠️ **别用文件时间戳判断"同步了没有"**：Node 的 `fs.copyFile` 与 Capacitor 的 `copy`
> 在 Windows 上都会**保留源文件的 mtime**，所以 `assets/public/` 里各文件的时间戳本来就新旧不一
> （跟 `www/` 里对应文件一致）。要确认同步真的发生，**比对内容**（例如 `grep` 一个特征串），
> 或者直接查 APK：`unzip -l` / 用 Python 的 `zipfile` 读（`jar tf | grep` 会被判成二进制而截断）。

仓库**不包含** `android-app/`，需要自行补回后才能执行 `npm run sync:web` / `npm run build:apk`。

### 为什么这样分目录

四个目录职责互不重叠，**不要合并**：

| 目录 | 性质 | 关键约束 |
| --- | --- | --- |
| `web/` | 源码（进版本库） | 同时是**静态服务的根目录**，白名单 `[web/, web/live2d/models]` |
| `data/` | 运行时私密数据（gitignore） | **刻意在静态根之外** —— 所以 `store.json`（含 API Key 与聊天记录）、`auth.json`、证书**不可能被下载** |
| 根目录 `*.md` | 文档 | 不参与运行 |
| `scripts/` | 开发工具 | 不参与运行 |

把 `web/` 并进 `data/` 会同时踩三个坑：源码脱离版本控制、`data/` 变成静态根（私密文件暴露风险从"结构保证"降级为"靠规则写对"）、
`DATA_DIR = <web 的上一级>/data` 会推导成 `data/data`。

> 运行时数据**全部**收在 `data/` 下（store / auth / 证书 / 日志）。`web/.local-auth.json` 是历史遗留位置，
> 升级后首次启动会自动迁移过去，详见「十、访问控制与安全」。

## 已知限制

### 数据备份（v1.1.0 新增功能）

- **安卓版的导出/导入未在真机上实测** —— 只在模拟环境下验证过调用路径（写文档目录、列出备份、读回）。
  真机行为（能否写入、系统文件管理器能否看到）需要你确认后反馈
- **导出文件包含 API Key 明文**（`elainachat_open_api_secrets` 与备份一起出去）。
  分享备份给他人前**务必自己检查** —— 界面上有提示，但还没有"导出时排除密钥"的选项
- **导入是整体覆盖式合并**（按键覆盖），没有逐项 diff 让你挑选。备份里同一张卡如果你本机已改过，
  导入会直接覆盖本机版本，只靠一次确认弹窗提示，没有版本对比
- **迁移只在启动时跑一次**。如果在服务运行期间手工往 `store.json` 里塞了分类键，不会触发迁移（重启即可）

### Live2D

- **参数绑定情况由模型作者决定**，换模型必须重新验证。有些模型会出现「参数存在但设了没反应」（作者把标准参数名留空），可以用 `/diag-param-bind.html` 扫描
- 带 `2` 后缀的角度变体（`ParamAngleX2` / `ParamAngleY2`）语义不可靠，可能是整体位移而不是转头，本改版已排除不驱动
- 鼠标跟随的头部幅度受模型自身参数量程限制，多数模型在约 1.5 倍时到顶，更高倍率由身体跟随补足
- 模型尺寸记忆按模型名存储，跨设备切换屏幕后比例会按当前屏幕高度钳制
- 安卓端 Live2D 未实测
- 上传大 zip（超过 50 MB）时内存占用较高
- 自签证书在手机上需要手动点击「继续前往」；想彻底免掉这一步需要正式 CA 签发的证书（局域网 IP 签不了）
- 局域网为明文 HTTP 时密码在传输中不加密，建议只在可信网络中使用

### 对话接口

- **本地中转只在页面由 `serve.mjs` 提供时生效**。直接双击 `index.html`（`file://`）打开时不走中转，
  服务商不发 CORS 头就仍然连不上 —— 这也是推荐用 `启动.bat` 的原因
- 从局域网用手机访问时，请求会经宿主机 Node 转发。**宿主机必须能访问该服务商**（宿主机断网 / 被墙时手机也连不上）
- Node 的 `fetch` **不读 `http_proxy` / `https_proxy` 环境变量**。如果只有走系统代理才能访问服务商，
  中转会失败并报出具体原因（`getaddrinfo` / `ECONNREFUSED` 等），此时需要在系统层做透明代理
- 中转目前是**非流式**转发（与前端一致，对话本来就等完整回复）；接口本身支持逐块透传，将来上流式无需再改服务端
- **部分服务商的 `/v1/models` 拿不到**（无 CORS 头、预检 405），此时「获取模型」必然失败 —— 不影响对话，把模型名手填进输入框即可
- **「获取模型」报错时会说清到底拿到了什么**：Base URL 少了版本段（如只填 `https://newapi.gay`）
  时 `/models` 会打到站点首页、拿回一页 HTML。这种提示是「返回的是网页（HTML），不是 API 响应」
  并附上**实际请求的地址**与补 `/v1` 的建议 —— 不会再说成"该服务不支持 /models"（那会把人带偏）
- **上游报错文案可能误导**（例如说 system 位置不对、其实是不接受多条 system）。已做客户端兼容处理，换服务商时建议直接看同名 `.trace.log` —— 那里有上游返回的**原始响应体**
- **追踪日志含完整对话内容**，是隐私面。启动横幅会提醒，设置 → 高级 → 日志 里可关闭；把 `data/logs/` 整个发给别人等于把聊天记录一起发出去
- **日志级别只过滤文件，不过滤终端**（刻意的，见上）。想让终端也安静只能重定向输出
- **改级别只影响之后的记录**，不追溯已有内容；切到 `WARN` 后翻旧文件仍会看到当时的 `INFO`

### Anthropic 格式

- **「获取模型」可用**：Anthropic 有 Models API（`GET /v1/models`），返回结构和 OpenAI 同构，应用已适配。
  Base URL 填裸域名（`https://api.anthropic.com`）或带 `/v1` 都可以，应用会自己补对版本段。
  第三方中转若只认 `Authorization: Bearer`（不认 Anthropic 的 `x-api-key`），应用会自动换一种再试。
  万一还是拉不到，把模型名手填进输入框即可 —— 不影响对话。
- **拉到列表后会自动填进模型名输入框**。若框里已有你手填的值，它**不会被覆盖**（只把下拉框切到第一项，
  点一下即可换过去）；只有"空"或"切格式时自动填的预设名"才会被覆盖 —— 后者通常不在真实列表里，
  留着必然 404（详见交付文档 8.24）。
- **应用内的「思考模式」开关在这里是空操作**。它只在 DeepSeek 官方端点下用于换成 `deepseek-reasoner`；Anthropic 原生的 `thinking` 参数尚未支持
- **模型名带 `-thinking` 会让每次对话都走扩展思考**（更慢、更贵），应用只在你撞上 400 时才会提示这件事
- **这条 `-thinking` 的坑不只影响 Anthropic 格式**：中转站的校验是跨协议的，用「OpenAI 兼容」调 Claude 同样会撞上，所以 `max_tokens` 的保底三种格式都有（见上一节的说明）
- Anthropic 的 `temperature` 取值是 **0~1**（OpenAI 是 0~2）。目前应用不传这个参数，所以撞不上；将来若开放设置项需要单独钳制

### 日志

- **请求头一律不记录**（`Authorization` 就在里面，落盘等于把 API Key 写到磁盘上）。代价是排查「认证类」问题时看不到到底发了什么头，只能靠状态码与响应体推断
- 单文件超 8 MB 会拆成 `_2` / `_3`，**同一次启动的日志被分到多个文件**，看的时候要连着看
- `SIGTERM` 在 Windows 上无法可靠送达，外部强杀进程时不会有收尾行 —— 以文件里最后一个时间戳为准

### Agent 文件操作

- **只能在网页版用**（需要 `serve.mjs` 提供 `/api/agent/*`）；APK 里没有这个服务端，标签会被判为不可用
- 真实位置靠**注册表**读出来。优先走 PowerShell（输出用 Base64 包一层，避免中文路径被代码页打碎），
  失败再退到 `reg.exe`，都读不到就按惯例猜 —— 企业策略把两者都禁掉时，桌面被移动过就会找不到
- 一次运行只解析一次（起进程不便宜，且这些路径在一次运行内不会变）。**改了桌面位置要重启服务**
- **没有删除 / 重命名 / 移动权限**，只有列出、读取、写入
- **覆盖已有文件需要确认**：写入已存在的文件会被服务端拦下（`needOverwrite`），
  经你同意后才落盘。每个对话只问一次；新建文件不打扰
- **应用文件夹模式禁止写 `.html` / `.js` / `.svg` 等可执行类型**（它们落进 `web/` 会以同源身份
  被执行，等于存储型 XSS）。这条防护曾能被 `x.html::$DATA` 这类 Windows 写法绕过，已修
- **「允许操作电脑」模式不做类型限制**（你已授权它操作电脑任意路径）。但 AI 若在该模式下把
  `.html` 写进 `web/`，同源风险依然成立 —— 这是刻意留给用户的取舍
- **两种模式都不允许"静默修改"**：这是刻意的共同下限 —— 再开放也不该在你不知情时改写已有文件
- **`.html` 写入防护不是完整边界**：`computer` 模式本来就不做类型限制（本机与已登录的局域网设备都一样），
  而且有了命令执行之后，`echo x > web/a.html` 这类写法被危险判定归为 **safe**（重定向目标不是绝对系统路径），
  不带授权就能落盘。所以它防的是"模型顺手写个文件"，不是"铁了心要注入的人"——
  **真正的边界是"要不要给命令执行"这个开关本身**
- **「允许操作电脑」对局域网的开放，把密码变成了单点**：登录后的手机/平板可以执行任意命令。
  密码强度（≥8 位含数字+大小写）与防爆破（指数退避 + 全局限流）是配套的必要防护，
  但**密码一旦泄漏就等于整台电脑失守** —— 没有第二层。请只在可信网络里开这个模式

### AI 手机操作

- **悬浮窗权限必须手动开**：`SYSTEM_ALERT_WINDOW` 是 Android 的特殊权限，只能在系统设置里打开
  （应用无法弹权限框索取）。**没开的时候，每一步确认都要你切回本应用来点 ——
  而切回来会让被操作的应用退到后台，那一步操作就可能失败。** 请到
  设置 → 能力 → 手机操作 → 「开启悬浮窗」按提示打开
- **副屏监视窗**：AI 用「模块」后端时跑在独立虚拟副屏上，物理主屏看不到。
  任务进行中运行状态条上会出现「看画面」，点开可实时看它在点什么、界面变成什么样。
  只在模块后端时出现（无障碍 / Shizuku 是在物理屏上操作，你本来就看得见）
- **副屏监视窗的真机表现未验证**：能否稳定拿到帧、1.5 秒自动刷新会不会拖慢副屏，
  只在代码层验证过（65 项检查），需要真机确认
- **Agent 循环仍跑在 WebView 里** —— 应用切到后台时被系统节流会导致长任务走一半停住。把它搬到前台服务是下一步要做的（真机上最容易遇到的坑）
- 手机操作**只在安卓版 App 里可用**，网页版没有原生设备层（执行时会明确提示）
- `su -c id` 能否拿到 `uid=0` 依 KernelSU / Magisk 版本而异，未逐版本验证
- 无障碍的 `dispatchGesture` 是否被某些 ROM 拦截、`ACTION_SET_TEXT` 在具体输入框里的表现 —— 只能真机确认
- **Shizuku 的 UserService 绑定稳定性未在真机验证**（四种实现方式里最没底的一项）
- 模块网关（本机 3070 端口）的真实接口路径与字段名未对着真模块跑过（代码做了字段名兼容）；
  副屏监视窗依赖同一网关，所以它也一并未实测
- 各厂商后台管理下长任务是否被掐断未验证；厂商适配的坑除小米 / OPPO 两条来自 Shizuku 官方文档外，其余是社区经验
- 中文输入的实际表现未验证
- **悬浮窗本身的真机表现未验证**：浮层显示/拖动/按钮点击、以及"应用退到后台浮层仍在"这条
  只在代码层验证过（42 项检查），需要真机确认

### Live2D

- **内置模型现在有兜底**：模型列表会**合并**打包进 APK 的那份清单
  （直接读 `/live2d/models/manifest.json`，不依赖任何原生插件）。所以即使
  "播种到应用数据目录"这一步失败（权限、存储、ROM 限制），内置模型照样能用
- **模型尺寸/位置记忆按模型名存**，跨设备切换屏幕后比例会按当前屏幕高度钳制
- 标签协议目前是文本标签 + 正则解析，还没升级成带 JSON Schema 校验的正规 Tool Calling
