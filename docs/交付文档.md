# 📦 ElainaChat-Open 改造版 — 交付文档

> 基于 MIT 开源的 [ElainaChat-Open](https://github.com/KaimeranFeran/ElainaChat-Open) 二次开发，新增 **Live2D 视频通话**、**视觉模型图片转述**、**设置分栏** 等能力。

---

## 1. 项目概述

| 项 | 说明 |
|---|---|
| 项目名 | ElainaChat-Open（改造版） |
| 技术栈 | 纯前端单 HTML + Node 静态服务（零依赖） |
| 定位 | BYOK（自带 Key）AI 角色聊天 + Live2D 视频通话 |
| 运行方式 | `node web/serve.mjs`，端口 4173 |
| 平台 | Web + 安卓（Capacitor） |

## 2. 核心功能

### 2.1 聊天
- OpenAI 兼容 / Anthropic / Gemini / Ollama 多格式（BYOK）
- 角色卡、世界观、分层提示词、记忆整理、图片输入
- TTS 多服务商：MiniMax / 阿里 Qwen-TTS / 豆包 / OpenAI / 浏览器
- ASR：浏览器识别 / 阿里百炼

### 2.2 🎥 Live2D 视频通话（新增）
- 顶部栏「📹 视频通话」按钮 → 全屏通话界面
- **模型外挂**：应用内上传 zip（`web/live2d/models/`，gitignore 不入库）
- 模型选择下拉 + 删除
- **模型大小/位置调节（通话界面调整框）**：底部「📐 调整」按钮开关调整框——
  - 框贴合模型实际绘制范围（非画布留白），默认隐藏、每个模型独立记忆位置/大小
  - 角手柄等比缩放（Shift 自由拉伸）、边手柄单轴、框内拖动移动
  - −/＋ 按钮等比微调 ±10%
- **背景设置**（设置页：预设渐变 / 纯色 / 自定义颜色 / 图片）
- **AI 说话嘴部同步**（LipSync，嘴型幅度随情绪变化：激动张嘴大、平静/伤心小）
- **💧 水印开关（通用自动探测）**：若模型 exp 目录含"水印/watermark"开关表情（如悠小喵「水印开关」→ Param85=1、泠等），打开通话后按键盘 **1 / 0** 切换水印隐藏/显示，也可由 AI 用 `[操作:隐藏水印]` / `[操作:显示水印]` 触发（**通话界面没有水印按钮**），直接驱动参数、比 expression 播放可靠，每个模型记忆开关状态
- **🎤 说话（真实语音输入）**：底部「🎤 说话」按钮，点击开始录音（复用主应用 ASR：阿里百炼 / 小米 MiMo / 浏览器），再点结束发送；聆听时按钮变红脉冲
- **底部栏精简**：只保留 🎤 说话 / 📐 调整 / 📞 挂断（AI 声音静音开关与 −/＋ 大小按钮已移除；静音仍可由 AI `[操作:静音]` 标签触发，大小调整用 📐 调整框拖拽）
- **AI 状态驱动（标签协议，AI 自主决策）**：LLM 回复可用 `[情绪:开心|难过|生气|害羞|惊讶|委屈|思考|平静]`（自动映射表情+嘴型幅度）、`[表情:xxx]`、`[动作:xxx]`、`[位置:left|center|right|上|下]`、`[大小:大|小|特大|特小|65%]`、`[背景:深蓝|星空|…]`、`[操作:打开视频通话|结束通话|整理记忆|静音|取消静音]` 标签驱动模型表现与应用功能；无标签时按触发词/emoji 自动推断情绪；标签均不显示给用户
- **跨模型自适应（AI Agent 决策）**：模型列表接口返回每个模型的 exps/motions（.exp3/.motion3 文件名）；系统提示词**动态注入当前模型可用表情/动作列表**，由 AI 根据情景直接选用真实文件名（`[表情:哭哭]` 等），换任何 Live2D 模型都自动适配；语义键（`[表情:happy]`）与情绪词（`[情绪:开心]`）经 语义映射 → 精确 → 子串/同义词组 三级解析兜底；表情参数用 `setParameterValueById` 直接驱动（比库的 expression() 可靠）
- **⏰ AI 定时任务（未来消息）**：LLM 可用 `[任务:每天 09:00 提醒我喝水]` / `[任务:明天 14:00 …]` / `[任务:每3小时 …]` / `[任务:每周五 18:00 …]` / `[任务:30分钟后 …]` 创建定时任务；调度器每 30s 检查，到点 AI 以角色身份自动发消息（插入当前对话 + 可选浏览器通知），支持周期/一次性；设置 → 高级可查看和取消；系统提示词已注入标签指南引导模型自然使用
- **🤖 AI Agent 权限分级（设置 → 高级）**：`[操作:列出文件 路径]` / `[操作:查看文件 路径]` / `[操作:保存文件 路径|内容]` 文件操作按权限模式受限：**🔒 限制模式**（默认）仅可读写本应用文件夹（web/），**💻 允许操作电脑**模式可读写任意路径（经本地服务执行，风险自担）；操作结果以「【AI 操作结果】」消息回填对话作为上下文；应用内操作（视频通话/记忆/水印/背景/静音）两种模式都可用
- **LLM 表情/动作驱动**：回复含 `[表情:xxx]` / `[动作:xxx]` 标签 → 模型自动做表情/动作（标签不显示）
- 麦克风开关（关 = 模型闭嘴 + AI 静音）

### 2.3 👁️ 视觉模型图片转述（新增）
- 设置 → 视觉：配一个 OpenAI 兼容的视觉模型（如 Qwen-VL）
- 图片对话时：**视觉模型先看图转述成文字 → 交给主模型（如 DeepSeek）回答**
- 未配视觉模型时：图片直接发给当前模型（原行为）

### 2.4 设置分栏（新增）
设置面板改为 6 个 Tab：**角色 / 对话 / 语音 / 视觉 / Live2D / 高级**

## 5. 配置说明

### 5.1 对话模型（设置 → 对话）
- API 格式：openai / anthropic / gemini / ollama
- 填 BaseURL + Key + 模型名（BYOK，Key 存当前标签页 sessionStorage）

### 5.2 视觉模型（设置 → 视觉）
| 字段 | 说明 |
|---|---|
| API 地址 | OpenAI 兼容，如 `https://api.siliconflow.cn/v1` |
| API Key | 视觉模型 Key |
| 模型名 | 如 `Qwen/Qwen2.5-VL-72B-Instruct` |

### 5.3 Live2D（设置 → Live2D）
- **上传模型**：选 .zip（Live2D Cubism 3 模型，含 `.model3.json` + `.moc3` + 纹理）
- **模型选择**：下拉切换已上传模型
- **背景**：渐变/纯色/自定义/图片
- **大小**：通话界面 −/＋ 调节

### 5.4 语音（设置 → 语音）
- TTS：MiniMax / 阿里 Qwen-TTS / 豆包 / OpenAI
- ASR：浏览器 / 阿里百炼

## 6. 服务端 API（serve.mjs）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/live2d/upload` | POST | 上传模型 zip，解压到 `web/live2d/models/<id>/` |
| `/api/live2d/models` | GET | 列出模型（含 model3.json 路径） |
| `/api/live2d/models/<name>` | DELETE | 删除模型目录 |
| 静态服务 | GET | 主页面 + vendor + 模型文件 |

### zip 解压实现要点（已修复）
- **中文文件名**：支持 UTF-8 标志位 + GBK 兜底解码（Windows zip 常见 GBK）
- **data descriptor**：支持（PowerShell Compress-Archive 生成的 zip 带此标志）
- **目录名**：用英文安全 id（`model_xxx`），展示名保留中文
- **防目录穿越**：路径白名单校验

## 7. Live2D 技术要点（踩坑记录）

### 7.1 库组合（关键！）
```
live2dcubismcore.min.js           # Cubism 3/4 核心（必须）
pixi-6.min.js                     # PIXI 6.5.10（必须 6.x）
pixi-live2d-display-cubism4.min.js # 纯 Cubism4 版（必须用这个！）
```

**⚠️ 不要用 `pixi-live2d-display` 的 `index.min.js`（混合版）**——它强制要求 Cubism 2 运行时（`live2d.min.js`），而 Cubism 2 核心很难获取（官方 CDN 404、npm 无），会导致 `PIXI.live2d` 挂载失败。

**正确文件来源**：`pixi-live2d-display@0.4.0` npm 包里的 `dist/cubism4.min.js`（纯 Cubism 4，不需要 Cubism 2）。

### 7.2 模型加载
```js
// 等待 cubism4 就绪
if (PIXI.live2d?.cubism4Ready) await PIXI.live2d.cubism4Ready;
const model = await PIXI.live2d.Live2DModel.from('/live2d/models/<name>/<model3.json>', { autoInteract: false });
```

### 7.3 嘴部同步
```js
model.internalModel?.coreModel?.setParameterValueById?.('ParamMouthOpenY', value);
// 模型 model3.json 需有 LipSync 组（悠小喵有）
```

### 7.4 表情/动作
- 表情：`model.expression('/live2d/models/<name>/exp/<表情>.exp3.json')`
- 动作：`model.motion('/live2d/models/<name>/exp/<动作>.motion3.json')`
- LLM 输出 `[表情:happy]` 等标签 → `drive()` 解析触发 → `stripTags()` 剥离

### 7.5 诊断页
`http://localhost:4173/diag-live2d.html` —— 检查三库加载、`PIXI.live2d` 是否挂载。

## 8. 已解决的问题（历史）

| 问题 | 解决方案 |
|---|---|
| 模型太大超出屏幕 | 按模型高度自适应（占屏幕 65%），底部居中 |
| 上传 zip 解压乱码/错乱 | 修复 UTF-8/GBK 编码 + data descriptor 解析 |
| 中文模型名路径问题 | 目录用英文 id，展示名保留中文 |
| `PIXI.live2d` 不存在 | 换用纯 Cubism4 版库（不用混合版） |
| 设置页每个 Tab 都显示角色卡 | Tab 用独立类 `active-panel`（避开 `.hidden` 动画类冲突） |
| 视觉模型设置位置突兀 | 移到独立「视觉」Tab |

### 8.1 上游同步（2026-08，origin/main 5888a75，PR#3 + PR#4）

合并上游最新修复到本地定制版（stash → fast-forward → pop，无冲突）：

| 上游修复 | 说明 |
|---|---|
| `replaceChildren` 兼容垫片 | Chromium < 86 无 `Element.prototype.replaceChildren`，发送图片会在 `consumePendingComposerImage` 抛 TypeError。脚本开头仅在缺失时注入垫片（`web/index.html` + `android-app/www/index.html`） |
| `inset` 长属性兜底 | 旧 WebView（Chromium < 87）不支持 `inset` 简写，fixed 浮层会飘到左上角。改为 `top/right/bottom/left` 长属性 + 新增 `.fixed.inset-0 { top:0; right:0; bottom:0; left:0 }` 兜底规则 |
| ASR 防重入修复 | 桌面 Chrome 连续 `start()` 报 "recognition has already started"。新增 `asrStarting` / `asrRecognitionActive` / `asrSessionId` 三态守卫：startListening 防重入、onend 重启校验会话 id、切回浏览器 ASR 前先 abort/stop 旧会话 |

**本地定制额外兜底**：`web/live2d-video.js` 内联样式中的 `#live2d-call-host`（fixed 全屏通话层）与 `.live2d-canvas-wrap` 同样改用长属性 `top/right/bottom/left`，避免旧 WebView 下视频通话界面飘左上角（上游补丁不覆盖此文件）。

> 注意：`android-app/www/index.html` 已同步上游修复，但**未包含** Live2D/视觉/设置分栏定制（维持前开发者"安卓端纯开源版"的约定）。如需同步定制版到安卓，运行 `node scripts/sync-web.mjs` 前请先确认 vendor 里三个 Live2D 库文件已复制到 `android-app/www/vendor/`。

### 8.2 Live2D 模型调整（通话界面调整框，最终方案）

原 −/＋ 按"高度占屏幕比例"缩放存在两个问题：加载后立即读 `model.height`（未就绪时为 0 → scale 异常）且无法调整比例/位置。曾尝试设置页实时预览 + 滑块方案，但用户更偏好通话界面直接拖拽，最终定为**通话界面调整框**（`web/live2d-video.js`）：

- **「📐 调整」按钮开关**：底部栏新增，点击显示/隐藏调整框（默认隐藏，按钮高亮表示开启）
- **调整框贴合模型实际绘制范围**（非画布留白），每帧跟随；角手柄等比缩放（Shift 自由拉伸）、边手柄单轴、框内拖动移动
- 存储为绝对 PIXI scale + 中心位置比例，**每个模型独立记忆**（`live2d.resize.<模型名>`），自动迁移旧 `live2d.resize` / `live2d.scale`；渲染高度钳制在屏幕高的 2%~600%
- −/＋ 按钮等比微调 ±10%（保留）

### 8.3 修复记录（2026-08 二轮）

| 问题 | 根因 | 修复 |
|---|---|---|
| 每个分栏都有角色设定卡 | 上游旧版遗留 JS `settingsContent.appendChild(characterSettingsSection)` 在页面加载时把角色卡**移出** `tab-character`，落到设置内容末尾；它不是 tab panel（无 display:none），任何 Tab 下都可见 | 删除该移动逻辑，角色卡保留在 `tab-character` 内 |
| 调整框与模型对不齐、模型比例变形 | **`live2d-canvas-wrap` 在 HTML 里是 class，代码却用 `getElementById` 获取 → 永远 null**：`resizeTo` 失效、手动 resize 被跳过，canvas 保持默认 800×600 被 CSS 拉伸（764×485），模型变形、框偏移 | ① 给 div 补上 `id="live2d-canvas-wrap"`；② 渲染循环每帧核对 canvas 内部分辨率与容器 CSS 尺寸，不一致立即 `renderer.resize` 并重算布局；③ 框定位乘 `canvas.clientWidth/canvas.width` 校正因子（双保险） |
| 模型水印隐藏（悠小喵/泠 等） | 模型作者在 VTube Studio 里绑定了数字键（悠小喵=1、泠=0）触发"水印开关"表情（`水印开关.exp3.json` → `Param85=1`），但 pixi-live2d-display 不解析 vtube.json，且其 `expression()` 播放 Add 参数不生效 | **通用水印开关**：`serve.mjs` 模型列表接口新增返回 `exps`/`vtube`；前端自动探测 exp 目录含"水印/watermark"的表情 → 读出参数 Id 与隐藏值 → 键盘 1/0 切换（也可由 AI 用 `[操作:隐藏水印]` 触发），**直接 `setParameterValueById` 驱动参数**（比 expression 可靠），按模型记忆开关状态 |
| Live2D 背景换色无反馈 | 设置页点击色块/自定义颜色/图片/清除背景后直接应用，无任何 UI 反馈，用户不确定是否成功 | 新增 toast 提示（"✅ 背景已应用"等）+ 色块选中高亮（`.l2d-bg-opt.selected` 描边），打开设置时同步当前背景的选中状态 |
| 无法局域网访问 | `serve.mjs` 默认监听 `127.0.0.1` | 默认改为监听 `0.0.0.0`，启动时打印本机局域网 IP 地址（如 `http://<你的局域网IP>:4173`），可用 `HOST`/`PORT` 环境变量覆盖 |
| 浏览器语音识别报错难懂（network / not-allowed 等） | 报错直接透出 Chrome 的英文错误码，用户不知道怎么办 | ① `friendlyAsrError()` 把错误码翻译成可操作提示（network→"需连接在线语音服务，建议阿里云"、not-allowed→"权限/环境限制，建议 localhost/https 或阿里云"、audio-capture/no-speech 等）；② `onerror` 降级扩展：network / service-not-allowed 与权限错误一样，配置了阿里云时自动切"录音+云端最终识别"不打断用户；③ `startListening` 检测非安全上下文（局域网 IP/手机 http 访问）直接友好提示 |
| 语音识别浏览器支持不明确 | Firefox 等无 SpeechRecognition API，提示含糊 | **明确仅支持 Chrome**：`isChromiumBrowser()` 检测（UA + userAgentData 双通道），非 Chromium 浏览器点击麦克风直接提示"语音识别仅支持 Chrome（含 Edge 等 Chromium 内核浏览器）"；Chromium 但 API 缺失提示"未启用/版本过旧，请用最新版 Chrome" |
| 语音报"recognition has already started" | Chrome 的竞态：abort/stop 后立即 start()（或 onend 后立即 start()）会抛该错误；更严重的场景是**旧实例卡死**（某次异常退出 onend 未触发，实例永久停留 running，abort 也救不回），之后每次 start 都失败 | 新增 `safeStartRecognition()` + **实例重建**：捕获 "already started" → `abort()` 重置 → **`rebuildBrowserRecognition()` 丢弃旧实例、`createBrowserRecognition()` 创建全新实例并重新绑定事件** → 300ms 后重试（最多 3 次）。新实例状态干净必定可启动；`onstart` 严格置位、`endListening` 提前清标志；重试耗尽才提示"引擎状态冲突，请稍候/刷新页面" |
| 浏览器语音识别反复不可用 | Chrome 语音识别受网络（依赖 Google 服务）与环境（需 https/localhost）双重限制，用户环境无法稳定使用 | **标注"暂不可用"**：设置 → 语音中"浏览器内置识别"加红色「（暂不可用）」标注，选中时显示警告提示改用阿里云 |

### 8.4 第三轮：参数"静默失效"专项修复（2026-09）

这一轮的核心发现：**Cubism 运行时对不存在的参数名不报错**。`setParameterValueById('不存在的参数', 1)` 会被静默接受，`getParameterValueById` 甚至能读回刚写入的值（运行时把未知 id 追加到了参数表末尾），但该参数没有任何绘制绑定，画面完全不变。结果是代码"看起来生效、实际零效果"，且不产生任何日志。同理，**参数存在于模型里 ≠ 被绑定到绘制**——作者可能留下未使用的标准参数。

因此新增了一条硬规则：**情绪参数一律先取模型真实参数表，再按语义槽解析成真实参数名；解析不到就跳过并告警，绝不硬写。**

#### 实测数据（悠小喵，168 个参数）

冻结模型（停 motionManager / eyeBlink / breath / physics / pose，漂移基线压到 0）后逐个设值做像素 diff：

| 参数 | 结果 |
| --- | --- |
| `ParamCheekPuff` / `ParamEyeLOpen` / `ParamEyeROpen` / `ParamMouthOpenY` / `ParamMouthForm` / `ParamEyeBallX` | ✅ 有画面效果（已绑定） |
| `ParamSmile` / `ParamEyeLSmile` / `ParamEyeRSmile` / `ParamCheek` | ❌ 存在但未绑定 |
| `ParamBrowL` / `ParamBrowR` / `ParamBrowLY` / `ParamBrowRY` / `ParamBrowLForm` / `ParamBrowRForm` | ❌ 全部未绑定（该模型没绑眉毛） |
| `ParamEyeLOpening` | ❌ 存在但未绑定（实际用的是 `ParamEyeLOpen`） |
| **`ParamAngleX` / `ParamAngleY`** | ❌ **存在但未绑定** |
| **`ParamAngleX1` / `ParamAngleY1` / `ParamAngleY2`** | ✅ **真正绑定的转头参数** |

#### 修复清单

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 情绪参数组完全无效（P0） | `EMOTION_PARAM_SETS` 写死 `ParamSmile`/`ParamCheek`/`ParamBrowL`/`ParamEyeLOpening` 等，悠小喵里一个都不存在，且静默不报错 | 新增参数解析层：`refreshModelParamIds()` 取模型真实参数表 → `resolveParamId(slot)` 按语义槽 + 候选名/关键字解析；解析不到跳过并 `console.warn`。`EMOTION_PARAM_SETS` 改为语义槽（`smile`/`cheek`/`browL`/`eyeL`/`mouth`…） |

> 关键方法论：**验证 Live2D 参数是否真的生效，必须先停掉 motionManager / eyeBlink / breath / physics / pose，把漂移基线压到 0 再做像素 diff**。否则待机动画本身会产生约 15000 像素的噪声，任何结论都不可信（曾据此误判"参数有效"）。

### 8.5 局域网访问密码（新增）

服务默认监听 `0.0.0.0`（手机/平板可访问），但 Agent 文件接口没有鉴权、权限模式又由请求方自己传参决定 —— 不设访问控制时，同一局域网内任何设备都能打开应用、甚至读写本机文件。

规则：

- **本机（127.0.0.1）自动视为管理员**：免密进入，且可修改访问密码 —— 这也是忘记密码时的找回入口
- **局域网设备必须登录**：登录后种 HttpOnly Cookie 会话（7 天）
- 首次启动生成 12 位随机密码并在 cmd 窗口醒目打印；用户改过密码后只存 **scrypt 加盐哈希**，控制台不再显示明文
- 登录失败 5 次锁定 60 秒
- **CSRF 防护**：非 GET 请求校验 `Origin` 与 `Host` 同源，否则拒绝（防止任意网页在浏览器里悄悄改本机密码）
- **隐藏文件禁止静态访问**：`.local-auth.json` 返回 403，避免密码文件被直接下载
- 改密码后清空所有会话，局域网设备需重新登录
- 忘记密码：本机打开 `http://127.0.0.1:4173` → 设置 → 高级 → 访问密码；或 `node web/serve.mjs --reset-password` 重启

凭据文件 `web/.local-auth.json` 已加入 `.gitignore`。

实测（curl）：局域网访问首页 302→`/login`、未登录 API 401、错误密码 401、正确密码 200+Set-Cookie、局域网改密码 403、本机改密码 200、旧密码失效、改密码后旧会话失效、伪造 Origin 403、`.local-auth.json` 403。

界面侧也做了端到端验证（设置 → 高级 → 访问密码）：面板能识别本机管理员并显示当前初始密码；两次输入不一致、密码少于 6 位都会被拦下并给出提示；正常修改后弹窗确认、状态文案变为"已由你自行设置"、输入框清空；随后用 curl 确认**旧密码失效、界面里刚设的新密码可在局域网登录**，且磁盘上只留下 `salt` + `hash`，没有明文。

> ⚠️ 局域网是明文 HTTP，密码在传输中不加密，建议仅在家庭/可信局域网使用。

**登录页配色**：与应用内**实际渲染值**（pixso 主题，非 `:root` 里那套）保持一致——橄榄绿画布 `#a8b974`、白色面板（`26px` 圆角 + `#d9c7c0` 描边 + `0 26px 70px rgba(58,39,29,.24)` 投影）、米色输入框 `#f8f5f2`、绿色药丸按钮 `#a7bb6c`、棕色文字 `#4c3123`、橙色小标 `#ff7d4d`。样式参数直接对齐应用内的 `.modal-panel` / `.modal-input` / `.btn-primary`，并加了一个和欢迎弹窗同款的橙色 eyebrow 小标。

> 踩坑记录：一开始抄的是 `:root` 里的 `--color-primary: #ec4899` 那套粉紫变量，但应用在运行时会用 pixso 主题覆盖它们，实际渲染出来是暖米色 + 棕 + 绿。**要取配色必须读渲染后的 computed style，不能只看 CSS 变量定义。**

**控制台输出精简**：`启动.bat` 的横幅（Server / Local / LAN / Press Ctrl+C）与 `serve.mjs` 里的接口清单、诊断页地址等提示行全部移除，只保留必要信息：

```
  可在「设置 → 高级 → 访问密码」改成自己的，改完这里就不再显示。
```

### 8.6 鼠标跟随：修正"整体位移"并加开关（2026-09）

修好头部追踪后暴露出的新问题：鼠标一动，**整个模型会朝鼠标方向下沉前倾**，看着像扑过来，很突兀。

逐参数看变化区域后定位到元凶：

| 参数 | 变化像素 | 变化区域 |
| --- | --- | --- |
| `ParamAngleX1` | 6075 | 宽 128 × 高 417（局部） |
| `ParamAngleY1` | 4896 | 宽 132 × 高 417（局部） |
| **`ParamAngleY2`** | **29343** | **宽 158 × 高 525（连水印层一起动）** |

`ParamAngleY2` 并不是"低头/抬头"，而是把整个模型（含作者加的水印层）一起推移——单独设它就复现了"靠过来"的画面。

修复：`headX` / `headY` 的候选只保留 **标准名** 和 **1 号变体**，不再驱动 `2` 号变体（`ParamAngleX2` / `ParamAngleY2`）。带 `2` 的变体在不同模型里可能是整体位移或整体旋转，语义不可靠，宁可不驱动。

同时新增 **鼠标跟随开关**（设置 → Live2D → 鼠标跟随），可整体关闭；关闭时立即把角度参数复位，模型保持不动。状态存在 `localStorage` 的 `live2d.mouseFollow`。

修复后实测：`ParamAngleY2` 恒为 0；鼠标左右移动时 `ParamAngleX1` 从 −17.9 → +17.9，画面变化 5930 像素、变化区域高度从 519 降到 417（只剩局部）；关闭开关后移动鼠标，所有角度参数保持 0，模型完全不动。

### 8.7 标签解析：情绪标签会吞掉操作标签（重要修复）

`live2d-video.js` 的 `driveText()` 里原本是：

```js
const emo = t.match(/\[情绪[:：]\s*([^\]]+)\]/);
if (emo) {
  driveEmotion(emo[1].trim());
  return;   // ← 问题在这里
}
// 后面的 [位置] / [大小] / [背景] / [操作] 全部在这行下面
```

那个 `return` 的本意只是"有显式情绪就别再做自动推断"，但它把**后面所有标签一起跳过了**。而系统提示词明确要求 AI **每条回复都带一个情绪标签**（`LIVE2D_TAG_GUIDE`：「每条回复根据内容带 1 个情绪/表情标签」）。

后果：`[操作:…]` 标签（文件操作、打开/结束视频通话、整理记忆、静音、隐藏水印）**在实战中几乎永远不会被执行**；`[位置]` / `[大小]` / `[背景]` 同样失效。更糟的是 `stripTags()` 会把标签从显示文本里剥掉，用户看不到标签被忽略，AI 还可能顺着说"已经帮你打开了"——正好踩中提示词里明令禁止的"编造操作结果"。

> 补充：`[任务:…]` 不受影响，它由 `index.html` 的 `extractAndCreateTasks()` 独立解析。

**修复**：把"跳过自动推断"改成只用一个布尔标志控制，不再提前返回；顺带支持**一条回复里出现多个 `[操作:…]`**（例如同时"打开视频通话"+"隐藏水印"）；未知情绪词也不再整条跳过，而是回退到自动推断。

修复后实测（对 `agentActions` 打桩记录调用，7/7 通过）：

| 场景 | 结果 |
| --- | --- |
| `[情绪:开心]…[操作:打开视频通话]` | ✅ 操作不再被吞 |
| `[操作:打开视频通话][操作:整理记忆]` | ✅ 两个操作都执行 |
| `[情绪:难过][操作:列出文件 D:\笔记]` | ✅ 参数完整传递 |
| `[情绪:平静]`（只有情绪） | ✅ 不误触发操作 |
| `[情绪:开心][背景:星空]` | ✅ 背景生效 |
| 无情绪标签时 | ✅ 原路径未改坏 |
| `[情绪:莫名其妙]…`（未知情绪） | ✅ 回退推断且操作照常执行 |

- [ ] 带 `2` 及以上后缀的角度变体（`ParamAngleX2` / `ParamAngleY2`）语义不可靠：在悠小喵上 `ParamAngleY2` 会推动整个模型而不是转头，因此已排除不驱动。若某个模型把头部的俯仰**只**绑在 `Y2` 上，需要单独适配
- [ ] 鼠标跟随的幅度（X 轴 ±20°、Y 轴 ±16°）是固定值，未做设置项；若某个模型看起来幅度过大/过小，需要按模型调整
- [ ] Live2D 模型二次发布限制：模型目录已 gitignore，但**用户上传的模型版权需自行注意**
- [ ] 安卓（Capacitor）端 Live2D 未实测（网格手柄交互同样未在安卓 WebView 实测）
- [ ] 上传大 zip（>50MB）内存占用较高（整包读入内存）
- [ ] 尺寸记忆按模型名存储，但不同屏幕尺寸（手机/桌面）共用一份，跨端切换屏幕后比例会按当前屏幕高度钳制

## 10. 常见问题（FAQ）

**Q: 视频通话提示"模型加载失败：Network error"？**
A: 模型文件不在 `web/live2d/models/` 里（被清理或未上传）。重新在设置 → Live2D 上传，或把模型文件夹放进去。

**Q: 上传 zip 后找不到 model3.json？**
A: zip 需包含 `.model3.json` 文件（Cubism 3 模型）。确认 zip 里有，且解压后路径正确。

**Q: 背景/大小没生效？**
A: 强刷（Ctrl+F5）清缓存。背景在设置 → Live2D 里选；大小/位置在视频通话底部点「📐 调整」打开调整框，拖手柄缩放、框内拖动移动（角手柄等比，Shift 自由），−/＋ 可等比微调。

**Q: 浏览器语音识别用不了/报错？**
A: 打开 `http://localhost:4173/diag-asr.html` 语音识别诊断页，先点「测试麦克风」再点「开始语音识别测试」，页面会显示：环境检测（Chromium 内核/安全上下文/API）、麦克风权限结果、实时转写、事件日志和诊断结论（含解决建议）。把结果反馈给开发者即可快速定位。

**Q: 模型水印怎么隐藏（悠小喵按 1、泠按 0）？**
A: 这类模型自带"水印开关"表情（exp 目录里的 `水印开关.exp3.json` 等）。打开视频通话后，若模型有水印开关，按键盘 **1 / 0** 即可切换水印隐藏/显示，也可以直接让 AI「把水印隐藏掉」（它会用 `[操作:隐藏水印]` 触发）。**通话界面没有水印按钮**，只能靠键盘或 AI 触发。开关状态按模型记忆。任意模型只要 exp 目录含"水印/watermark"命名的表情都会自动支持，无需改代码；若某个模型水印机制特殊（无开关表情），需要按模型单独适配。

**Q: AI 回复里的 `[表情:xxx]` 没触发模型表情？**
A: 检查模型 exp 目录是否有对应表情文件；`EXPRESSION_MAP` 是否匹配（悠小喵：happy→星星眼、sad→哭哭、blush→脸红…）。
